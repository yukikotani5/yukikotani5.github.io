# 小谷祐樹 ポートフォリオサイト

potofu の置き換えとして作った、自分専用のポートフォリオサイトです。
**研究業績・ICUトーク・note は毎日自動で最新になります。**

---

## お問い合わせフォームについて（設定済み）

フォームは Web3Forms 経由で、**キーに紐づけたメールアドレス**に届くよう設定済みです。
（宛先は web3forms.com 側で管理されているので、このリポジトリには書いていません）
キーは `assets/app.js` の先頭にあります。

```js
const FORM_ACCESS_KEY = "dd09459b-cd85-4606-bb0b-00db06162823";
```

- 迷惑な送信が増えたら、<https://web3forms.com> でキーを再発行して貼り替えれば止まります
- キーはブラウザから見える場所に置く必要があり、公開リポジトリでは誰でも読めます。
  これは Web3Forms の設計どおりで乗っ取られる類のものではありませんが、
  送信枠（無料枠は月250件）を他人に使われる可能性は理論上あります
- フォームには人には見えない項目を1つ仕込んであり、ボットが埋めると送信を止めます

## 公開する

GitHub Pages で公開する場合：

**公開済みです： https://yukikotani5.github.io/**

リポジトリ `yukikotani5/yukikotani5.github.io` の main ブランチに push すると、
GitHub Actions が自動でデプロイします。毎朝6時（日本時間）の自動更新も同じ仕組みです。

`data/` のファイルを書き換えたら、これを実行するだけです。

```bash
cd ~/kotani-portfolio && ./scripts/publish.sh "9月の説明会を追加"
```

このスクリプトが以下をまとめてやります。

1. `data/*.json` の書式チェック（壊れていたら止めます）
2. コミット
3. 自動更新のコミットを取り込む
4. push

`git` を直接使う場合は、**必ずコミットしてから pull** してください。
順番を間違えると push が弾かれます。

## 自動更新のしくみ

`.github/workflows/update.yml` が **毎朝6時（日本時間）** に `scripts/update.py` を実行します。

| 掲載しているもの | 取得元 | 自動更新 |
|---|---|---|
| 研究業績（被引用トップ5） | PubMed + ORCID + OpenAlex | ✅ |
| ICUトーク（最新回 / 最多再生回） | YouTube | ✅ |
| note（最新記事 / 最多スキ記事） | note API | ✅ |
| Voicy（最新話 / 最多再生話） | Voicy 内部API | ✅ |
| 取材記事の画像 | 各記事の OGP | ✅（URLを書けば自動で拾います） |

手元で試すには：

```bash
python3 scripts/update.py
```

### Voicy について（非公式APIを使っています）

Voicy は RSS も公開 API も出しておらず、チャンネルページも JavaScript 描画なので
HTML からは何も取れません。そこで **Web版が内部で使っている API** を同じ手順で叩いています。

1. Firebase の匿名サインインで `idToken` を取得
2. その Bearer トークンで `vmedia-player-api.voicy.jp` の stories API をページング

**これは公式に公開されたAPIではありません。** 予告なく仕様が変わったり塞がれたりする可能性があります。
そうなっても `update.py` は失敗した系統だけを飛ばし、**前回取得した値をそのまま残す**ので、
サイトの表示が壊れることはありません（GitHub Actions のログには警告が出ます）。
気になる場合は `update.py` の `voicy()` の呼び出しを外し、値を手で書く運用に戻せます。

なお、ページ上の「再生順」表示はその時点で読み込まれている分しか並べ替えないため、
**画面で1位に見える話が本当の1位とは限りません**（実際、画面上は227回が最多に見えましたが、
全409話を取得すると本当の最多は435回の別の回でした）。スクリプトは全話を取得してから最大値を求めています。

### 同姓同名の別人が混ざらないようにしています

「Kotani Y」で PubMed を検索すると、**大阪の整形外科医や東京大学の化学者など、別の研究者の論文が21件ヒットします**。
そのため検索条件を所属（亀田総合病院 / San Raffaele大学）で絞っています。

```python
PUBMED_QUERY = 'Kotani Y[Author] AND (Kameda[Affiliation] OR "San Raffaele"[Affiliation])'
```

**ここを緩めると別人の論文が載ります。** 変更するときは `python3 scripts/update.py` のあと、
必ず一覧を目視で確認してください。

### 被引用数について

PubMed は被引用数を持っていないため、**OpenAlex** から取得しています。
サイトに出している「よく引用されている論文5本」はこの数字の降順です。
返信・訂正・論説は原著と区別して除いてあります。

### 業績を過大に見せない工夫

「原著論文」の件数は、`The authors reply` のような**返信・訂正・論説を除いた**数です。
統計の数字と、掲載している論文の判定条件は必ず揃えてあります。

## 手で編集するファイル

自動更新の対象外です。中身を書き換えるだけで反映されます。

| ファイル | 内容 |
|---|---|
| `data/profile.json` | 自己紹介、経歴、資格・学会活動、SNSリンク、依頼の種類 |
| `data/writings.json` | 原稿執筆（**日本語**で書いた論文・解説記事）|
| `data/news.json` | トップのお知らせ（イベント告知など）|
| `data/talks.json` | 講演・セミナー |
| `data/media.json` | 取材・インタビュー |

**新しい取材を受けたら** `data/media.json` の `items` に1ブロック足してください。
日付順の並べ替えはサイト側が自動でやります。

```json
{
  "date": "2026-09-01",
  "outlet": "媒体名",
  "title": "記事タイトル",
  "url": "https://...",
  "type": "インタビュー",
  "excerpt": "一言紹介（省略可）"
}
```

`url` さえ書いておけば、**記事ページのサムネイル画像は自動で取り込まれます**
（各ページの OGP 画像を読みに行き、`"image"` に保存します）。
別の画像を使いたいときは、自分で `"image": "https://…"` を書けばそちらが優先されます。

### 英文論文と和文の書き分け

| | どこに載るか | 更新 |
|---|---|---|
| 英文論文（国際誌） | 研究業績（被引用トップ5） | 自動 |
| 和文論文・解説・寄稿 | 原稿執筆 | 手動 |

セクションを分けずに済むよう、原稿執筆の各行に **種別のバッジ**（和文論文／寄稿／解説／総説）を出し、
両セクションの説明文からお互いへリンクしています。

### トップの「お知らせ」について

`data/news.json` に書いたものと、**執筆・講演・取材の新着が自動で混ざって**、新しい順に5件表示されます。
同じ内容を二重に書く必要はありません。`news.json` に書くのは、イベント告知など
どのセクションにも入らないものだけです。

### 亀田ICUオンライン説明会を毎月足すとき

`data/news.json` の `items` の先頭に1ブロック足すだけです。

| 状況 | 書き方 | 表示 |
|---|---|---|
| 日時だけ決まった | `"url": ""` のまま | 告知のみ（緑の「開催予定」） |
| 応募リンクが出た | `"url"` に貼る | 見出しがリンクになり、申し込みボタンが出る |
| 受付が終わった | `"status": "受付終了"` | グレーの「受付終了」になり、ボタンが消える |

日付が今日より先のものが先頭にまとまって出ます。開催日を過ぎると自動で下がります。

### 一覧が長くなったら

**和文論文・原稿執筆**と**講演・セミナー**は、最新5件だけ表示して、
下の「すべて表示（○件）」を押すと全部開きます。件数が5件以下のときはボタンが出ません。
表示件数を変えたいときは `assets/app.js` の `initCollapse(..., 5)` の数字です。

### 原稿執筆を足すとき

`data/writings.json` の `items` に足してください。`kind` に種別を入れます。書誌情報は
[CiNii Research](https://cir.nii.ac.jp/) で誌名・巻号・ページを確認すると確実です。

```json
{
  "date": "2026-10",
  "kind": "解説",
  "journal": "救急医学",
  "publisher": "へるす出版",
  "citation": "50(11):1234-1240",
  "feature": "特集 ○○（省略可）",
  "title": "記事タイトル",
  "authors": "小谷祐樹",
  "url": "https://cir.nii.ac.jp/crid/…（省略可）"
}
```

自動化していない理由：CiNii で「小谷祐樹」を検索すると
**溶接工学の同姓同名の研究者の論文が20件以上ヒットします**。
自動で拾うと別人の業績が載りかねないので、ここは手で管理する形にしています。

```
kotani-portfolio/
├── index.html                  ← 本番のページ
├── assets/
│   ├── style.css
│   ├── app.js                  ← フォームのキーはここ
│   └── profile.jpg
├── data/
│   ├── profile.json            ← 手で編集
│   ├── writings.json           ← 手で編集（原稿執筆）
│   ├── news.json               ← 手で編集（お知らせ・イベント）
│   ├── talks.json              ← 手で編集（講演）
│   ├── media.json              ← 手で編集（取材）
│   ├── publications.json       ← 自動（被引用トップ5）
│   └── feeds.json              ← 自動（ICUトーク・note・Voicy）
├── scripts/
│   ├── update.py               ← 自動更新の本体
│   └── build_preview.py        ← 1ファイル版を書き出す
└── .github/workflows/update.yml
```

## 手元で見る

`index.html` はデータを読み込む都合でサーバーが必要です。

```bash
python3 -m http.server 4321 --directory .
```

`http://localhost:4321` を開いてください。

サーバーなしで見たい・誰かにファイルで渡したいときは、1ファイル版を作れます。

```bash
python3 scripts/build_preview.py
```

`preview.html` ができます（ダブルクリックで開けますが、中身は作った時点で固定されます）。

## アクセス解析

GoatCounter で計測しています（Cookieを使わないので同意バナーは不要）。
計測タグは `index.html` の末尾、ダッシュボードは https://yukikotani5.goatcounter.com/

数字を要約して見るには：

```bash
python3 scripts/stats.py        # 直近30日
python3 scripts/stats.py 7      # 直近7日
```

**APIトークンはリポジトリに置きません。** 次のファイルから読みます。

```
~/.config/kotani-portfolio/goatcounter.env
```

トークンを作り直したときは、このファイルの `GOATCOUNTER_TOKEN` を差し替えてください。
発行画面（Settings → API tokens）の**「統計の読み取り」にチェックが要ります**。
サイト設定ページにある Secret token とは別物で、そちらでは 401 になります。

### 集計期間の指定に注意

GoatCounter の `end` は**その日を含みません**。`stats.py` は内部で +1日して渡しています。
ここを直接いじると、当日ぶんが落ちて `total` だけ 0 になり、気づきにくい形で壊れます。
（`total_utc` のほうには数字が出るので、食い違っていたらこれを疑ってください）

### 週次レポートの自動実行

毎週月曜の朝、Claude が自動でレポートを作ります。設定はここです。

```
~/.claude/scheduled-tasks/portfolio-weekly-analytics/SKILL.md
```

曜日・時刻を変えたい、やめたいときは、アプリのサイドバーの「Scheduled」から操作できます。
**Claude のアプリを開いているあいだに実行されます。** 実行時刻に閉じていた場合は、
次にアプリを開いたときに走ります。

過去のレポートは追記で溜まっていきます。

```
~/.config/kotani-portfolio/weekly-reports.md
```

## デザインについて

モチーフは**波形トレース**です。ICUのモニター波形とポッドキャストの音声波形は同じかたちをしていて、
「集中治療医」と「ポッドキャスター」という2つの顔を1本の線で結べると考えました。
ヘッダーのマークと名前の下の線が、それです。

書体は Zen Maru Gothic（丸ゴシック）で親しみやすさを、
誌名や年号などのデータには IBM Plex Sans を当てて、業績部分は読みやすさを優先しています。
ライト／ダークどちらの表示にも対応しています。
